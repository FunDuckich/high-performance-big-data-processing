# Лабораторная VI — потокобезопасные контейнеры

Исходный вариант: 20. Вариант задания: 8 из 12.

На сетке 400 × 400 вычисляется

```text
f(x,y) = сумма по k,j=1…50: sin(kx) sin(jy) / ((1+k³+j³) sqrt(1+k+j)).
```

Сохраняются только точки с `∂f/∂y ≤ 0`. В производной sin(jy) заменяется на j cos(jy). Как в исходном примере, шаг сетки — 2π/400, индексы 0…399: периодическая граница 2π второй раз не включается.

Сравниваются обычный vector с concurrent_vector и обычная queue с concurrent_queue. У каждой пары своя последовательная база времени. Время включает вычисление, отбор и добавление точек.

## Что сравниваем и как понимать результат

Здесь мало независимо посчитать значения: нужно безопасно добавлять отобранные точки в общий растущий контейнер. В предыдущих вычислительных лабах выходные ячейки были заранее выделены и у каждой задачи была своя. Здесь позиции для новых элементов организуют `concurrent_vector` и `concurrent_queue`.

Вектор хранит последовательность с доступом по индексу, очередь предназначена для добавления в конец и извлечения из начала. Их внутреннее согласование параллельных операций различается. В этом запуске вектор быстрее очереди; по одному замеру нельзя приписать весь разрыв конкретному механизму. Главное — одинаковый набор выбранных точек и ускорение относительно своего последовательного контейнера. Порядок параллельных вставок заранее не задан.

## Что сказать на защите

«Разные потоки вычисляют разные строки сетки, но выбранные точки нужно складывать в общий контейнер. Обычный push_back или push в один общий контейнер небезопасен при одновременном вызове из нескольких потоков. Concurrent-контейнеры поддерживают такое добавление. Порядок появления точек может отличаться, поэтому я сравниваю наборы по индексам узлов, а не по порядку вставки».

## По коду

`evaluate` одновременно считает функцию и производную. `selected_point` проверяет условие. `Point.index` нужен для проверки результатов. После завершения параллельного цикла данные из контейнеров сравниваются с последовательным эталоном; чтения очереди одновременно с её заполнением нет.

## Запуск и настройки

Запуск: `run.bat` в этой папке или готовый `.exe` в `bin/Release`. В Visual Studio откройте корневой `Labs.sln`, назначьте эту лабу запускаемым проектом, выберите Release x64 и нажмите Ctrl+F5.

Размеры и настройки находятся в начале [main.cpp](main.cpp). После изменения выполните из корня `build.bat lab06`. Командных параметров нет. Время включает работу алгоритма, проверка и печать выполняются после замера.

Краткие замеры на этом ПК: [results.txt](../results.txt). Подробности проверок и конфигураций: [проверки проекта](../docs/verification.md).

## Результат на проверочном компьютере

В проверочном запуске concurrent_vector дал ускорение 5,88 раза, concurrent_queue — 5,07 раза относительно своего последовательного контейнера. Все четыре способа сохранили одинаковые 80145 точек. Условие применяется к вычисленной double-производной, включая эффекты округления около нуля. Это один запуск на Ryzen 5 3600; на другом компьютере время и соотношение методов могут измениться.
