# Проверки и результаты

Дата: 2026-10-20. Процессор: AMD Ryzen 5 3600, 6 физических ядер, 12 логических процессоров. Windows 10.0.26200, x64.

## Сборка и корректность

- Все семь проектов собраны в Release x64 наборами MSVC **v143 (14.44)** и **v142 (14.29)**. Для v142 использована его установка внутри Build Tools 2022; это проверка старшего и младшего компиляторов, а не отдельной IDE Visual Studio 2019.
- Все семь проектов собраны в Debug x64 с v143. При проверке внутри песочницы служба PDB была недоступна; та же сборка вне песочницы завершилась успешно без изменения проектов.
- Восемь групп проверок (`tests/run.bat`) прошли на v143 и v142: по группе на каждую лабораторную и отдельно таблицы. Эталоны ряда перенесены из прежних независимых расчётов Decimal с точностью 55 знаков; интеграл сверяется с независимым векторизованным расчётом и сгущением сетки.
- Полные запуски всех семи Release-программ с размерами из исходников завершились с кодом 0, все сравнения результатов дали `OK`.
- В VI сохранено 80145 точек из 160000. Условие отбора применяется к производной, вычисленной в double; очень близкие к нулю значения могут зависеть от округления.
- В VII при y = 1 получено примерно **0,51987316216566**. Расхождение последовательного и параллельного результатов — **1,5654·10⁻¹⁴**. Проверены y = 0, 1, π/2, удвоение сетки, увеличение числа множителей и верхнего предела; изменения меньше 1e−8.

## Перенос и запуск

- Семь готовых `.exe` скопированы за пределы репозитория в папку с пробелами и кириллицей. Все полные запуски выполнены там, из другого рабочего каталога, с PATH только на системный каталог Windows. SHA-256 копий совпадают с распространяемыми файлами.
- `dumpbin /dependents` у каждой из семи программ показывает только **KERNEL32.dll**. Отдельные DLL Visual C++ и Concurrency Runtime не требуются.
- Исходники с решением и общими настройками скопированы в другую папку с кириллицей и пробелами. `build.bat lab01` успешно собрал проект с относительными путями.
- Проверены сборка одной лабы, отказ при неизвестной лабе/лишнем аргументе и понятная ошибка при имитации отсутствия Visual Studio.
- Проверены `run.bat` с настоящей программой, сообщение при отсутствующем `.exe`, пауза и передача ненулевого кода программы (контрольный код 7).
- Таблицы проверены на длинных русских подписях, больших числах, нулевом времени и узком окне. Ширина всех строк таблицы совпадает; в узком окне используется вертикальный вывод.
- Внешняя чистая установка Windows, сама IDE Visual Studio и компилятор v141 от VS 2017 недоступны и не проверялись. Поддержка VS 2017 предусмотрена стандартом C++14 и выбором текущего набора инструментов; готовые Release `.exe` от установленного компилятора доступны независимо от этого.

## Выводы

- I–II: независимые тяжёлые вычисления ускорились примерно в 5,6–6 раз. Малые различия между контейнерами по одному запуску не дают оснований объявлять один контейнер всегда лучшим.
- III: parallel_sort оказался быстрее buffered-версии. Дополнительный буфер не гарантирует выигрыша.
- IV: быстрее всего оказался radixsort; здесь меняется и способ сортировки, поэтому ускорение может превышать число физических ядер.
- V: task_group дал ускорение примерно 5,7 раза. Независимость задач позволила загрузить несколько ядер.
- VI: concurrent_vector в этом запуске быстрее concurrent_queue. Их главное свойство для задачи — безопасное одновременное добавление точек.
- VII: combinable ускорил суммирование примерно в 6,8 раза. Последние знаки отличаются из-за порядка сложения, а не из-за разных формул.
