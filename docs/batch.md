# Что делают батники

Все сценарии используют UTF-8 и окончания строк Windows CRLF. Они ничего не скачивают и не устанавливают, не вызывают Git.

## Общие команды

| Команда | Смысл |
|---|---|
| `@echo off` | Не печатать каждую исполняемую команду |
| `setlocal` | Переменные сценария не меняют окружение вызывающего терминала |
| `chcp 65001 >nul` | Переключить консоль на UTF-8, скрыть служебный ответ команды |
| `set "ИМЯ=значение"` | Записать переменную; кавычки защищают пути с пробелами |
| `%~dp0` | Диск и папка самого батника, независимо от текущего каталога |
| `%~1`, `%~2` | Первый и второй аргументы без внешних кавычек |
| `call` | Запустить другой батник и затем вернуться |
| `if errorlevel 1` | Проверить, что предыдущая команда вернула ошибку |
| `goto метка`, `:метка` | Перейти к именованному участку сценария |
| `exit /b N` | Завершить батник с кодом N, не закрывая весь терминал |
| `pushd`, `popd` | Временно сменить каталог и затем вернуться |
| `pause` | Оставить окно открытым до нажатия клавиши |

## build.bat и scripts/find-tools.bat

`for %%L in (...)` проверяет имя лабы по списку из семи допустимых имён. Без имени выбирается цель `Build`, с именем — соответствующий проект. Второй аргумент и неизвестное имя отклоняются.

`vswhere` ищет последнюю подходящую установленную Visual Studio или Build Tools. `-products *` включает Build Tools, `-version "[15.0,)"` допускает VS 2017 и новее, `-requires` требует компоненты C++ и MSBuild. `for /f` сохраняет найденный путь. Затем выбирается расположение MSBuild: `Current` у новых версий или `15.0` у VS 2017.

| Параметр MSBuild | Смысл |
|---|---|
| `/t:Build` или `/t:lab04` | Собрать всё решение или выбранную лабораторную |
| `/p:Configuration=Release` | Оптимизированная сборка для измерения скорости |
| `/p:Platform=x64` | 64-битная программа, способная работать с большими массивами |
| `/m:1` | Собирать проекты по одному, без лишней нагрузки на память |
| `/nodeReuse:false` | Не оставлять процессы сборки для последующих вызовов |
| `/nologo`, `/verbosity:minimal` | Сократить служебный вывод |

Последовательная сборка проектов не ограничивает число потоков в готовых программах. В случае ошибки сценарий останавливается с кодом 1 и указывает на инструменты, которые нужно проверить.

## run.bat

Сначала `if not exist` проверяет наличие `bin\Release\labXX.exe`. Затем сценарий запускает эту программу. `set "LAB_RESULT=%errorlevel%"` сохраняет её код до исполнения других команд, `pause` сохраняет результаты на экране, `exit /b %LAB_RESULT%` возвращает исходный код.

Сам `.exe` тоже работает: при запуске в собственном окне он ожидает Enter. Батник удобен тем, что лежит сразу в папке лабы и объясняет, что делать при отсутствии программы.

## tests/run.bat

Подготавливает окружение MSVC через `VsDevCmd.bat`, компилирует отдельные проверки командой `cl` в игнорируемую папку `build/tests`, запускает их и останавливается при первой ошибке. `/std:c++14` выбирает стандарт языка, `/O2` — оптимизацию, `/MT` — статические библиотеки, `/EHsc` — обработку исключений C++, `/utf-8` — кодировку исходников, `/W4` — предупреждения.
