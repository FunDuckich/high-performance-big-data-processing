# Лабораторная III — параллельная сортировка

Исходный вариант: 20. Вариант задания: 8 из 12.

Последовательность: `xₙ = sqrt(n) / (1 + sqrt(n)) * sin(n)`, n = 0…N−1, N = 50 000 000. Контейнер — vector<double>.

Сравниваются `std::sort`, `parallel_sort`, `parallel_buffered_sort`. Перед каждым методом восстанавливается исходный массив. Параллельные результаты полностью сравниваются с результатом `std::sort`.

## Что сравниваем и как понимать результат

Все три метода упорядочивают одни и те же числа по возрастанию. `std::sort` выполняет последовательную сортировку, параллельные методы распределяют части работы между потоками. `parallel_buffered_sort` дополнительно использует рабочий буфер: это другой способ организации сортировки с дополнительным расходом памяти.

Смотрим на точное совпадение массивов и время. В нашем запуске выиграл `parallel_sort`. Буфер сам по себе не гарантирует ускорения: его выделение и обращения к памяти тоже стоят времени. Это возможные факторы различия; один замер без профилирования не устанавливает точную причину. Ускорение относительно `std::sort` отражает и параллелизм, и различия реализаций алгоритмов.

## Что сказать на защите

«Я сортирую большой массив тремя способами. Обычная сортировка работает последовательно. Параллельные алгоритмы распределяют работу между потоками. Buffered-версия использует дополнительный буфер, поэтому расходует больше памяти; это не гарантирует, что она всегда быстрее. Победителя определяю по измерению на конкретном компьютере. Чтобы сравнение было честным, каждый метод начинает с одинакового неотсортированного массива».

## По коду

`value` создаёт один элемент последовательности. `input` хранит исходные данные, `reference` — эталон std::sort, `work` используется повторно для двух параллельных сортировок. Копирование выполняется до запуска таймера.

## Запуск и настройки

Запуск: `run.bat` в этой папке или готовый `.exe` в `bin/Release`. В Visual Studio откройте корневой `Labs.sln`, назначьте эту лабу запускаемым проектом, выберите Release x64 и нажмите Ctrl+F5.

Размеры и настройки находятся в начале [main.cpp](main.cpp). После изменения выполните из корня `build.bat lab03`. Командных параметров нет. Время включает работу алгоритма, проверка и печать выполняются после замера.

Краткие замеры на этом ПК: [results.txt](../results.txt). Подробности проверок и конфигураций: [проверки проекта](../docs/verification.md).

## Результат на проверочном компьютере

В проверочном запуске std::sort занял 5,327 с, parallel_sort — 0,717 с, parallel_buffered_sort — 0,828 с. Быстрее оказался parallel_sort: 7,43 раза относительно последовательной сортировки. Это один запуск на Ryzen 5 3600; на другом компьютере время и соотношение методов могут измениться.
