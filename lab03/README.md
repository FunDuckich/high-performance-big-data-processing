# Лабораторная III — параллельная сортировка

Исходный вариант 20; `(20 - 1) % 12 + 1 = 8`.

```text
N = 50 000 000
x_n = sqrt(n) / (1 + sqrt(n)) · sin(n)
n = 0,...,N-1
```

Контейнер — `std::vector<double>`. Сортировка по возрастанию выполняется тремя способами: `std::sort`, `concurrency::parallel_sort`, `concurrency::parallel_buffered_sort`. Каждый метод получает исходную неотсортированную последовательность.

## Запуск

Двойной щелчок по `run.bat` запускает полное задание и оставляет результаты в окне. Из терминала в этой папке:

```powershell
.\bin\Release\lab03.exe
.\bin\Release\lab03.exe --size 100000
.\bin\Release\lab03.exe --repeats 3
```

`--help` показывает параметры. Сборка из корня исходного проекта: `build.bat lab03`. Для готовой программы требуется Windows 10/11 x64, компилятор не нужен. `.exe` работает самостоятельно; `run.bat` сохраняет окно для чтения результатов при двойном щелчке.

Три основных вектора полного размера занимают около 1,2 ГБ; `parallel_buffered_sort` требует дополнительного буфера. Желательно иметь не менее 2 ГБ свободной памяти. При нехватке памяти программа выдаёт сообщение и ненулевой код возврата. Уменьшенный `--size` позволяет проверить запуск, но не заменяет измерение на полном наборе.

## Проверка и измерения

Генерация последовательности, восстановление рабочей копии и проверки не входят во время сортировки. Внутреннее выделение памяти алгоритмом входит в замер. Рабочий буфер переиспользуется между параллельными методами. Каждая сортировка проверяется на порядок, параллельные результаты точно сравниваются со `std::sort`. При повторах вычисляется медиана; `std::sort` выполняется первым, порядок двух параллельных методов чередуется. Отдельного прогрева нет.

Полный запуск 6 октября 2026 года: AMD Ryzen 5 3600, 6 ядер / 12 логических процессоров, 16 ГБ ОЗУ, Windows x64 (сборка 26200), MSVC 19.44, Release `/MT`. Размер 50 000 000, три повтора; в таблице медианы времени.

| Метод | Время, с | Ускорение относительно std::sort |
|---|---:|---:|
| std::sort | 5.377430 | 1.000 |
| parallel_sort | 0.663787 | 8.101 |
| parallel_buffered_sort | 0.710524 | 7.568 |

Параллельные результаты точно совпали со `std::sort`; все векторы упорядочены. Минимум равен `-0.999858560065`, максимум — `0.999858559919`. По медиане трёх повторов быстрее оказался `parallel_sort`: примерно в 8,1 раза относительно `std::sort`. Вариант с буфером дал ускорение около 7,6 раза. Это результат данного набора и окружения, а не универсальный порядок методов по скорости.

В используемой реализации PPL `parallel_sort` разделяет диапазон по принципу быстрой сортировки и обрабатывает поддиапазоны параллельно. `parallel_buffered_sort` сортирует части, затем параллельно сливает их с использованием дополнительного буфера размером с исходную последовательность. Для 50 млн значений double это ещё около 400 МБ. Буфер позволяет иначе организовать сортировку, но требует памяти и перемещения данных, поэтому его наличие не гарантирует меньшего времени. По одним замерам нельзя установить точную причину разницы: для этого потребовалось бы профилирование.
