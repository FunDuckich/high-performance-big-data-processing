# Лабораторная I — параллельные циклы

Исходный вариант 20; `(20 - 1) % 11 + 1 = 9`. Выполняются обе части файла I.

Вход: `x_n = 100 cos(n)`, `n = 1,...,2000`. Для каждого входа:

```text
M = max(20, floor(20 |x|))
f(x) = sum(k=1..M) sum(j=1..M)
       x² (k² + j²) / (x² + k⁴ + j⁴) · cos((k-j)x)
```

Первая часть сравнивает обычный цикл и `concurrency::parallel_for`, записывающие значения в вектор. Вторая сравнивает `std::for_each` и `concurrency::parallel_for_each` для `std::vector`, `std::deque`, `std::list`: элементы каждого контейнера заменяются на `f(x)`. Перед каждым измерением исходные значения восстанавливаются.

## Запуск

Двойной щелчок по `run.bat` запускает полную работу и оставляет результаты на экране. Из терминала в этой папке:

```powershell
.\bin\Release\lab01.exe
.\bin\Release\lab01.exe --size 16
.\bin\Release\lab01.exe --repeats 3
```

Быстрый запуск с `--size 16` не заменяет полный размер 2000. `--help` показывает параметры. Сам `.exe` не ожидает нажатия клавиши: для автоматизации используйте его, для двойного щелчка удобнее `run.bat`. Сборка из корня исходного проекта: `build.bat lab01`. Для запуска готового ZIP компилятор не нужен; требуется Windows 10/11 x64.

## Проверка и измерения

Время подготовки контейнеров не входит в замеры; локальные вычисления внутри `f` входят. Косинусы разностей и степени индексов предварительно вычисляются внутри каждого вызова `f`, порядок двойного суммирования сохранён. Обе версии используют одинаковую функцию. Проверяются все значения, их конечность и допустимая погрешность; выводится максимальная абсолютная ошибка. При нескольких повторах показывается медиана и чередуется порядок методов. Прогрева нет.

Полный запуск 6 октября 2026 года: AMD Ryzen 5 3600, 6 ядер / 12 логических процессоров, 16 ГБ ОЗУ, Windows x64 (сборка 26200), MSVC 19.44, Release `/MT`. Размер 2000, три повтора; в таблице медианы времени. Это измерение конкретного компьютера, а не гарантированное ускорение на других машинах.

| Сравнение | Контейнер | Последовательно, с | Параллельно, с | Ускорение |
|---|---|---:|---:|---:|
| for / parallel_for | vector | 5.046023 | 0.893666 | 5.646 |
| for_each / parallel_for_each | vector | 5.025812 | 0.872701 | 5.759 |
| for_each / parallel_for_each | deque | 5.035731 | 0.900637 | 5.591 |
| for_each / parallel_for_each | list | 5.042309 | 0.868897 | 5.803 |

Во всех четырёх сравнениях максимальная абсолютная ошибка равна нулю. Тяжёлая независимая обработка элементов дала ускорение для каждого контейнера: PPL распределяет вычисления разных элементов между рабочими потоками. Среди вариантов for_each наименьшая медиана получилась у списка, однако различие с вектором меньше 1%. Эти измерения не доказывают общего преимущества списка: здесь основная нагрузка приходится на вычисление функции, а не на обход контейнера.
