# Лабораторные по параллельным вычислениям

Три лабораторные по файлам I, II и III из архива «Задания-с-Исходниками.7z». Исходный вариант — 20. Номер внутри задания определяется по формуле `(20 - 1) % число_вариантов + 1`: для I и II выбран вариант 9 из 11, для III — вариант 8 из 12. В лабораторную I входят обе постановки из файла I.

## Запуск без установки программ

Готовый архив: `dist/labs01-03-windows-x64.zip`. Распакуйте его целиком, откройте папку нужной лабораторной и дважды нажмите `run.bat`. Можно переносить отдельную папку лабораторной, сохраняя её содержимое.

Требуется Windows 10/11 x64. Для готовых программ не нужны Visual Studio, CMake, Python и Visual C++ Redistributable: CRT и Concurrency Runtime связываются статически. Сборка не требует AVX/AVX2. Достаточный объём оперативной памяти всё равно необходим: в лабораторной III три основных вектора занимают около 1,2 ГБ, сортировка с буфером выделяет дополнительную память. Желательно иметь не менее 2 ГБ свободной памяти.

`run.bat` запускает готовую программу и ждёт нажатия клавиши после её завершения. Это позволяет прочитать результаты при запуске двойным щелчком. Он ничего не компилирует и не скачивает. Сам `.exe` можно запускать напрямую; при двойном щелчке его окно закроется после окончания работы. Из уже открытого терминала окно не исчезает:

```powershell
.\lab01\bin\Release\lab01.exe
.\lab02\bin\Release\lab02.exe --size 16
.\lab03\bin\Release\lab03.exe --size 100000 --repeats 3
```

Размер по умолчанию для I и II — 2000, для III — 50 000 000. Параметры `--size N` и `--repeats K` необязательны; повторов по умолчанию один, максимум 1000. При нескольких повторах выводится медиана времени. `--help` показывает справку. Размер должен быть положительным целым числом, не превосходящим 2147483647. Изменённый размер явно отмечается в выводе и не считается выполнением полного измерительного задания.

Параметры можно передать и сценарию: `.\lab01\run.bat --size 16`. Для автоматических запусков используйте непосредственно `.exe`, поскольку `run.bat` всегда ожидает нажатия клавиши. Ошибки параметров возвращают код 2, ошибки вычислений и нехватка памяти — код 1, успешное завершение — 0.

## Сборка из исходников

Нужны Visual Studio 2022 или Build Tools 2022 с компонентами C++ x64/x86, Windows SDK и CMake не ниже 3.20. CMake из компонента «C++ CMake tools for Windows» обнаруживается автоматически; отдельный CMake также можно добавить в PATH. На компьютере разработки эти инструменты уже установлены.

```powershell
.\build.bat
.\build.bat lab01
.\build.bat lab02
.\build.bat lab03
.\package.bat
```

`build.bat` находит инструменты через `vswhere`, подготавливает окружение MSVC x64, конфигурирует CMake и собирает Release. Без аргументов собираются все лабораторные и запускаются короткие автоматические тесты. С аргументом собирается только выбранная программа. Ошибка любого шага останавливает сценарий с ненулевым кодом. Готовые `.exe` находятся в `labXX/bin/Release`; служебные файлы — в `build`.

`package.bat` сначала выполняет полную сборку с тестами, затем через CPack создаёт переносимый ZIP. В нём находятся только готовые программы, сценарии запуска и инструкции. Пересобирайте архив после изменения исходников. Скрипты не устанавливают программы, не требуют прав администратора и не выполняют команды Git.

Исходники, общие заголовки, тесты и инструкции находятся в проекте. Каталоги `build`, `dist` и `labXX/bin` исключены через `.gitignore`: готовые `.exe` сохраняются на диске и в ZIP, но при обычном добавлении исходников в Git не попадут. Передача только исходного репозитория требует сборки; для компьютера без компилятора передавайте ZIP.

## Методика

Используются C++17, Microsoft PPL, Release x64, `/MT`, `/fp:precise`, стандартная оптимизация Release без `/fp:fast`. Время измеряется `std::chrono::steady_clock`. Выделение основных контейнеров, подготовка исходной последовательности, её восстановление, сравнение результатов и вывод не входят в замер. Внутренние затраты самого алгоритма, включая буфер параллельной сортировки и локальные таблицы функции, входят в него.

Каждый метод получает одинаковый исходный набор. В I и II при повторениях чередуется порядок последовательного и параллельного измерения. В III сначала вычисляется эталон `std::sort`, затем чередуется порядок двух параллельных сортировок. Отдельного прогрева нет; первый запуск включает возможную инициализацию планировщика PPL. Поэтому одиночный замер ориентировочный, для устойчивой оценки используйте `--repeats 3` и закройте тяжёлые фоновые приложения.

Ускорение равно времени последовательного метода, делённому на время сравниваемого. Значение меньше единицы означает замедление. Получение ускорения не является условием успешной проверки: важна корректность вычислений. Для численных результатов проверяются конечность и поэлементное совпадение с допуском `1e-10 * (1 + max(abs(a), abs(b)))`. Сортировки проверяются на упорядоченность и точное совпадение с `std::sort`.

В общей функции I–II косинусы разностей индексов и степени индексов вычисляются заранее внутри каждого вызова. Все методы используют одну и ту же функцию; пределы и порядок суммирования сохранены. Кэш результатов между алгоритмами не используется.

## Проверки

При полной сборке CTest проверяет независимые численные эталоны функции, чётность, границы усечения ряда, индексацию входов, сортировку пустого/одноэлементного/повторяющегося/упорядоченного наборов, небольшие запуски всех контейнеров и обработку ошибочных параметров. Эталоны получены отдельно с 55 десятичными знаками через Python Decimal и ряд Тейлора для косинуса; Python при запуске программ и тестов не нужен.

6 октября 2026 года прошли все 31 автоматическая проверка и полные запуски каждой лабораторной с размером из задания. В инструкциях отдельных лабораторных приведены медианы трёх повторов и выводы по ним. `dumpbin /dependents` показывает для каждой программы только системную `KERNEL32.dll`, без DLL Visual C++ и ConcRT.

Распакованный ZIP проверен вне репозитория в пути с пробелами и кириллицей, с PATH, содержащим только системный каталог Windows. Все три `.exe` и `run.bat` запускаются; сценарии сохраняют паузу и код ошибки программы, а при отсутствии `.exe` объясняют дальнейшие действия. Отдельная чистая установка Windows не использовалась.
