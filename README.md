# Лабораторные по параллельным вычислениям

Готовы лабораторные **I–VII**, исходный вариант **20**. VIII отложена до уточнения условия у преподавателя.

| Файл задания | Папка | Вариант | Размер по умолчанию |
|---|---|---:|---|
| I | [lab01](lab01/README.md) | 9 из 11 | 2000 значений; обе части файла I |
| II | [lab02](lab02/README.md) | 9 из 11 | 2000 значений |
| III | [lab03](lab03/README.md) | 8 из 12 | 50 000 000 значений |
| IV.docx | [lab04](lab04/README.md) | 8 из 12 | 50 000 000 значений |
| V | [lab05](lab05/README.md) | 9 из 11 | 1000 значений |
| VI | [lab06](lab06/README.md) | 8 из 12 | сетка 400 × 400, ряд 50 × 50 |
| VII | [lab07](lab07/README.md) | 5 из 15 | y = 1; 400 000 интервалов Симпсона |

Номер выбирается по кругу: `(20 - 1) % количество_вариантов + 1`.

## Просто запустить

Готовые программы лежат **прямо в репозитории**, в `labXX/bin/Release/labXX.exe`. После клонирования сборка не требуется. На GitHub отдельный `.exe` можно скачать через **Download raw file** на странице файла.

Откройте `run.bat` в папке нужной лабораторной либо сам `.exe`. Программа, запущенная двойным щелчком в собственном окне, ждёт Enter после завершения. `run.bat` также сохраняет окно с результатами. При запуске `.exe` из существующего терминала или с перенаправленным выводом дополнительной паузы нет.

Требуется **Windows 10/11 x64**. Готовым Release-программам не нужны Visual Studio, CMake, Python или отдельно установленный Visual C++ Redistributable: библиотеки C++ и Concurrency Runtime связаны статически. AVX/AVX2 не требуются. Лабы III–IV используют около 1,2 ГБ для трёх основных векторов и ещё примерно 400 МБ для буферной сортировки; желательно иметь не менее 2 ГБ свободной памяти.

Если памяти не хватает, уменьшите константу `N` в начале соответствующего `main.cpp` и пересоберите эту лабораторную. Размер выводится в консоль; уменьшенный размер нужно честно указать при сдаче.

## Открыть в Visual Studio

1. Дважды щёлкните **Labs.sln** в корне репозитория.
2. Выберите **Release** и **x64** в панели конфигураций.
3. В обозревателе решений нажмите правой кнопкой на нужной лабораторной и выберите **Назначить запускаемым проектом / Set as Startup Project**.
4. Откройте её `main.cpp` для просмотра кода. Для сборки и запуска нажмите **Ctrl+F5**.

Открывать только отдельный `main.cpp` не нужно: настройки находятся в проектах решения. Можно также открыть отдельный `labXX.vcxproj`; сохраните соседнюю папку `common` и структуру репозитория.

Для сборки нужна Visual Studio или Build Tools **2017 и новее** с набором **«Разработка классических приложений на C++»**, инструментами MSVC x64/x86 и Windows SDK. При установке только C#-компонентов C++ не соберётся. Проекты выбирают текущий набор инструментов установленной Visual Studio и установленный Windows 10/11 SDK, без привязки к SDK с конкретным номером. Фактически проверенные конфигурации перечислены в [проверках](docs/verification.md).

## Собрать через батник

```powershell
.\build.bat
.\build.bat lab04
.\lab04\run.bat
```

Без аргумента собираются все семь программ; с именем лабы — одна. Сборка и Visual Studio используют **одни и те же проекты**, результат записывается в `labXX/bin/Release`. CMake и скачивание дополнительных библиотек не нужны.

`build.bat` находит Visual Studio/Build Tools через `vswhere`, запускает MSBuild для Release x64, проверяет код завершения и сообщает результат. `run.bat` только запускает готовую программу и делает паузу. Подробности команд — в [пояснении батников](docs/batch.md).

## Где настройки и что подключено

Размеры заданы обычными константами в начале `main.cpp`. Параметров `--size`, `--repeats` и `Options` больше нет. Изменение настроек требует пересборки.

В каждой лабораторной видны формула, последовательный алгоритм, параллельный алгоритм и проверка. Один общий файл `common/support.hpp` содержит простой таймер, вывод результатов, сравнение чисел и работу консоли. `common/build.props` содержит общие настройки проектов, а не вычислительный код.

| Подключение | Зачем нужно |
|---|---|
| `../common/support.hpp` | Таймер, таблица и корректный русский вывод |
| `<ppl.h>` | Алгоритмы Microsoft PPL, `task_group`, `combinable` |
| `<concurrent_vector.h>`, `<concurrent_queue.h>` | Контейнеры с безопасным параллельным добавлением, только в VI |
| `<vector>`, `<deque>`, `<list>`, `<queue>` | Контейнеры стандартной библиотеки |
| `<algorithm>` | Последовательные алгоритмы и проверка результатов |
| `<cmath>` | Синус, косинус, корень и экспонента |
| `<cstdint>`, `<cstring>` | 64-битный ключ radixsort и безопасное копирование битов, только в IV |

## Что означают результаты

В каждой папке `lab01`–`lab07` есть README: условие, различия методов, объяснение работы, вывод по замерам и краткий текст для защиты. Общая сводка характеристик ПК, времени и выводов — [results.txt](results.txt).

Время измеряется по `std::chrono::steady_clock`. Каждому методу передаются одинаковые исходные данные. Генерация, восстановление массивов, проверка и печать исключены из замера. В VI создание выбранных точек и добавление в контейнер входят в работу метода. Внутренние буферы алгоритмов и планирование параллельной работы входят во время.

**Ускорение = Tпосл / Tметода.** Например, 4 означает «в четыре раза быстрее», 0,8 — замедление. Для очереди в VI базой служит последовательная очередь, для вектора — последовательный вектор. Один запуск даёт ориентировочный замер; его можно повторить вручную. Алгоритмы не обязаны ускоряться на каждом компьютере.

Столбцы автоматически расширяются по содержимому с учётом русских букв. В слишком узком окне результаты выводятся по строкам. `OK` означает совпадение результатов; численный допуск — `1e-10 * (1 + max(|a|, |b|))`, неконечные числа отклоняются. Сортировки сравниваются с `std::sort` без допуска.

## Проверки и исходные материалы

`tests\run.bat` собирает и выполняет отдельные численные и граничные тесты. Они не усложняют учебные программы и не запускаются автоматически при обычной сборке. Для тестов нужен тот же MSVC; Python и внешние пакеты не требуются.

Материалы: «Задания-с-Исходниками.7z» и лекции «MS-Concurrency-Runtime.pdf». В IV.pdf ошибочно продублирована VI, поэтому для IV используется DOCX. В VIII после 12 вариантов конвейера добавлены формулы другого задания; VIII пока не реализована.

Архив содержит примеры, но не готовые решения наших вариантов. В VI исправлены функция и условие отбора, в VII — подынтегральная функция. Подробности и текст для защиты находятся в папке каждой лабораторной.

В Git предназначены для хранения исходники, проекты, инструкции и семь Release `.exe`. Кэши, `.obj`, Debug-программы и настройки IDE игнорируются. После изменения кода пересобирайте Release-программы перед коммитом, чтобы исходники и `.exe` соответствовали друг другу.
